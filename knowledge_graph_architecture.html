Couche 1 — Connaissance Déclarative Métier

OKF — Open Knowledge Format

Fichiers .okf.md dans knowledge_base/. Formules métiers, règles business, seuils de performance, attributs sensibles par domaine.

medical_context.okf.md
IMC = Weight/(H²), MAP = (SysBP+2·DiaBP)/3, min_f1 ≥ 0.80, sensitifs: [Age, Gender]
concept_smote.md
Définition SMOTE, code Python, règle: train uniquement, jamais sur le test set
concept_roc_auc.md
Formule AUC, interprétation métier, quand privilégier Recall vs Précision
33 domaines couverts
classification, medical, finance, telecom, ecommerce, time_series, nlp, clustering…
--- (frontmatter YAML) ---
domain: medical
formulas:
  - name: IMC
    formula: "Weight / (Height ** 2)"
business_rules:
  recall_priority: true
  sensitive_attributes: [Gender, Age]
performance_thresholds:
  min_f1_score: 0.80
--- (fin) ---
📥 OKFReader.parse() → ingestion dans Neo4j au démarrage

Couche 2 — Ontologie de Concepts Structurés

knowledge_base/ — 33 Domaines comme Ontologie

Chaque dossier = un domaine. Chaque fichier .md = un concept parsé et importé comme nœud :Concept dans Neo4j. C'est la bibliothèque épistémique du système.

:Concept
name, definition, category, formula, token_estimate — issu du frontmatter .md
:Domain
medical, telecom, finance, classification, time_series… — 33 nœuds racines
:Tool
SMOTE, XGBoost, TabICL, Optuna, SHAP… liés aux concepts via [:IMPLEMENTED_BY]
:InterpretationRule
guideline + business_impact par domaine → injectées dans le prompt rapport LLM
🔗 MERGE Cypher temps réel — mémoire épisodique après chaque run
🧠
Couche 3 — Mémoire Vivante & Graphe d'Exécution

Neo4j — Graphe de Connaissances Dynamique

Combine connaissance statique (concepts) et mémoire épisodique (runs, alertes, remèdes). Évolue après chaque exécution. Accessible via KnowledgeGraphClient (TypeScript) et MCP Server (IDE).

:Run
id, taskType, status, metrics (JSON compact), strategy, timestamp
:Dataset
name, n_rows, n_cols — lié aux Runs et au Domain
:Model
RandomForest, XGBoost, TabICL — Champion lié au Run réussi
:Alert
overfitting, fairness_violation, low_cv_stability — via [:RAISED] / [:FAILED_WITH]
:Remedy
Solution de remédiation par type d'alerte (ex: pruning Optuna pour overfitting)
:DecisionTree
Règles gouvernance agentique : niveau supervision humaine requis avant pipeline
:BusinessCost
cost_FP, cost_FN, gain_TP, currency — par domaine (télécom: FN=25 000 FCFA)
:PerformanceThreshold
min_f1, min_r2, max_overfitting_gap — les Guardrails mathématiques configurables

Requêtes Cypher clés dans le pipeline
📚
RAG Stratégie — Concepts du domaine
Phase 2
MATCH (c:Concept)-[:BELONGS_TO]->(d:Domain)
WHERE d.name IN ["classification","medical"]
RETURN c.name, c.definition, c.formula
ORDER BY c.token_estimate ASC LIMIT 10
10 concepts les plus légers en tokens du domaine détecté — injectés dans le prompt LLM pour guider la stratégie de nettoyage.
🔮
Mémoire Épisodique — Runs similaires
Self-Healing RAG
MATCH (dom:Domain {name: $domain})
<-[:BELONGS_TO]-(ds:Dataset)-[:HAS_RUN]->(r:Run)
WHERE r.taskType = $taskType
  AND r.status = 'SUCCESS'
MATCH (r)-[:USED_MODEL]->(m)
RETURN ds.name, m.name, r.metrics
ORDER BY r.timestamp DESC LIMIT 3
3 derniers runs réussis du même domaine — résumés en ~30 tokens/run (compact) pour éviter le bloat du contexte LLM.
🚑
Remédiation d'alerte en live
Guardrail échoué
MATCH (rem:Remedy)
WHERE rem.name =~ $pattern
// ex: '(?i).*overfitting.*'
RETURN rem.name,
  rem.action, rem.code_snippet
LIMIT 1
Dès qu'un Guardrail échoue, le remède est extrait en live. Ex: "overfitting" → "augmenter l'élagage Optuna / réduire n_estimators".
🏛️
Gouvernance agentique
Supervision
MATCH (dt:DecisionTree {id: 'agentic-human-supervision'})
-[:HAS_BRANCH]->(b:DecisionBranch)
RETURN dt.question,
  collect({
    condition: b.condition,
    action: b.action}) AS rules
Règles de supervision humaine lues depuis le graphe — "Niveau 2 : Validation avant pipeline" déclenchée avant chaque exécution physique.

🔑 Principe clé : le Graphe comme Cerveau Distribué

  • Statique (concepts, domaines) : ingéré depuis knowledge_base/ → donne au LLM des connaissances ML sans réentraînement
  • Dynamique (runs, alertes) : mis à jour après chaque pipeline → le système apprend de ses erreurs via FAILED_WITH → RESOLVED_BY
  • Normatif (seuils, règles) : PerformanceThreshold + FairnessThreshold + BusinessCost par domaine → Guardrails configurables sans toucher au code
  • Compact par design : getTopSimilarRuns() retourne ~30 tokens/run (pas 2000+) → évite le bloat du contexte LLM
  • Fédéré : exportAnonymizedKnowledge() + importSharedKnowledge() → partage de connaissance entre instances (data sovereignty)
